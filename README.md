# 小笛 · QQ / Telegram 聊天机器人

一个**零依赖**的 Node.js（ESM）个人聊天机器人：同时支持 **QQ（OneBot / NapCat）** 与 **Telegram Bot API**，
带长期人格、表情包、语音、记忆归档、控制面板，以及（实验性）**用 ADB 驱动安卓模拟器"玩手机"**。

> 本项目是个人自用机器人，不是通用框架。代码风格偏"边跑边改"，但每一步都有自测断言盯着。

## 能力

| 模块 | 说明 |
| --- | --- |
| 双传输 | QQ 走 OneBot 协议（NapCat）／TG 走 Bot API 长轮询，二者共用同一套对话逻辑 |
| 人格 | 4000+ 字的角色设定 + 语气层（元气少女 / 俏皮毒舌），可热改 |
| 表情包 | 从本地图片库按标签取图，模型用 `[[图:标签]]` 标记点单 |
| 语音 | Windows SAPI 合成，失败自动降级成文字 |
| 识图 / 视频 | 图片交给视觉模型；视频用 ffmpeg 抽帧（每分钟 20 帧）拼图后再问 |
| 记忆 | 聊天按天归档到磁盘（jsonl）；`recall_chat` 可按关键词/时间回查 |
| **联想记忆** | 你提到身体/情绪/生活里的事时，**代码层**去归档翻你以前说过的话，带日期塞进本轮提示 |
| 搜索 | 天气、时间、网页搜索、搜图（pixiv → 网页兜底）、B站 视频信息与字幕 |
| 控制面板 | `panel-server.mjs`，浏览器里改配置、看日志 |
| 玩手机（实验） | ADB 驱动雷电模拟器：截图 → 视觉模型读屏 → 点按；点完用**帧比对**告诉她有没有点中 |

## 目录

```
qq-bot/
├── bot.mjs              # 主程序：消息路由、工具循环、prompt 组装
├── src/
│   ├── config.mjs       # 配置加载（config.json 覆盖默认值，热重载）
│   ├── llm.mjs          # 模型调用 + 工具循环（maxRounds 官方默认 4，本项目用 20）
│   ├── tools.mjs        # 工具声明与实现（21 个）
│   ├── intents.mjs      # 意图路由：能用代码确定执行的就不麻烦模型
│   ├── phone.mjs        # ADB 操作模拟器（只认 emulator-* 设备）
│   ├── phoneplay.mjs    # "自己玩一会儿"的流程（含 token 预算 / 时间上限）
│   ├── assoc.mjs        # 联想记忆：部位×症状识别 + 归档回查
│   ├── chatlog.mjs      # 聊天归档与检索
│   ├── stickers.mjs     # 表情包解析（含工具标记剥除）
│   └── telegram.mjs     # TG 传输层
├── tools/
│   ├── selftest.mjs     # 自测套件（800+ 条断言，零依赖）
│   ├── panel-server.mjs # 控制面板
│   └── win-control.ps1  # 窗口截图/控制（PowerShell + P/Invoke）
└── docs/
```

## 跑起来

```bash
node qq-bot/bot.mjs
```

需要的本地文件（**都不入库**，自己放）：

| 文件 | 内容 |
| --- | --- |
| `qq-bot/config.json` | 配置（没有就走 `src/config.mjs` 的默认值） |
| `qq-bot/telegram-token.txt` | TG Bot token |
| `qq-bot/.deepseek-key` | 模型 API key |
| `qq-bot/bili-cookie.txt` | B站 cookie（取字幕用，可选） |

## 自测

```bash
node qq-bot/tools/selftest.mjs
```

零依赖、纯 Node：起本地 mock 服务、跑真实消息链路、断言日志与副作用。

## 一些踩过的坑（写下来免得别人再踩）

- **Windows 上 `.ps1` 必须存 UTF-8 带 BOM**，否则 Windows PowerShell 5.1 按 GBK 解，中文注释直接让语法崩掉。
- **GUI 自动化一律用物理像素坐标**（per-monitor DPI-aware），DPI-unaware 的虚拟坐标和鼠标注入用的物理坐标混用会系统性偏移。
- **Unity 游戏没有无障碍节点**：`uiautomator dump` 返回 0 个元素，只能截图 + 网格 + 帧比对。
- **别用整图哈希判断"画面变了没"**：动画界面每帧都不同；要缩到 64×36 逐格比，>2% 才算变真。
- **代码层直接执行的意图要从严**：一句"继续"被判成"播放"就会去按系统媒体键，把用户正在办的事整个打断。

## 状态

个人自用项目，**边用边改**。稳定在跑的：双传输、记忆归档、联想记忆、表情包、语音、识图/视频、工具循环、控制面板。

**实验性**（可能随时改）：玩手机（ADB 驱动模拟器）—— 卡在「Unity 画面没有无障碍节点」这条限制上，
现在靠「截图 + 200px 网格 + 帧比对」硬撑：能看、能点，但**多步任务还不可靠**。

自测 **800+ 条断言**常驻绿色，改完就跑：

```bash
node qq-bot/tools/selftest.mjs
```
