# QQ bot + agent 协同：利弊清单（给你决策用）

> 写于 2026-10-09。全部结论都来自**今天实测**（含你看到的四次重启、五起"说了没做"），不是纸面推演。
> 一句话：**能力是量级提升，代价是复杂度、内存和"慢"**。要不要动，看你要的是"能干活"还是"聊天陪伴"。

---

## 一、要动的到底是什么（一句话）

**她还是她，只多一个"外援"。**

```
你 → 小笛（QQ 里，人格/记忆/秒回都不变）
       ├─ 闲聊、陪伴、记事儿、账号上的三件事   → 她自己干（和现在一样）
       └─ 「去查一下…」「帮我写个脚本」「看看我屏幕」
                    ↓ 转包
              外援 agent（机器上现成的 claude / codex 命令行）
                    ↓ 交出结果
              她用她自己的话告诉你（并把原文附在后面）
```

---

## 二、利（都是今天量出来的）

| # | 利 | 实测依据 |
| --- | --- | --- |
| 1 | **能做的事多一个量级** | 今天为了加"改签名"这一件小事：我写了 **23KB 代码**、你**重启了 4 次**、来回 6 轮才对。换成外援，那是一次调用的事 |
| 2 | **"她到底做没做"变得可查** | 今天一晚抓出 **5 起**"嘴上说做了、账号没动"（点赞/说说/签名/投币/资料）。走 agent 的话，动作变成**结构化的工具调用记录**，你可以像今天查日志一样查 |
| 3 | **现成的，不用装东西** | 已实测：`claude --print --output-format json` 一句话任务 **997ms** 返回，带 `session_id`（**能接着上次继续做**）；`codex exec --json -o <文件>` 同样可用。两个都在你机器上 |
| 4 | **桌宠会因为"她真在干活"而活起来** | 你机器上已装好的 `dsh-pet` 跟的就是 **agent 活动状态**（等待/思考/跑工具/成功/出错）。现在她只有聊天，桌宠就没东西可演 |
| 5 | **人格和记忆不会丢** | 人设是 `config.json` 里 **3922 字**的一段文本，记忆是 `memory.json`（19 条档案 + 日记）+ `sessions.json`。都是文件，换谁读都还是她 |
| 6 | **复杂任务能闭环** | 多步任务（查攻略 → 看画面 → 说一句；改配置 → 重启 → 验证）现在**一件都做不了**，因为每个动作都得我先写好 |

## 三、弊（同样按实测说，不美化）

| # | 弊 | 老实说 |
| --- | --- | --- |
| 1 | **慢**，而且和"闲聊"是两种节奏 | 闲聊现在 **1~1.5 秒**一条；agent 干真活要**几秒到几分钟**。所以只能"派出去、等它回来"，中间得先回你一句"我去做" |
| 2 | **吃内存，而且你内存很紧** | 常剩 **0.8~2GB**；claude/codex 进程本身几百 MB。所以**一次只能派一件**，而且有把 QQ/NapCat 挤死的风险（Electron 类程序在你机器上会**静默死**，这条早记过） |
| 3 | **权限面变大** | 外援能真的读写文件、跑命令。默认我会限制在**工作目录 + 要你点头**，但这条闸一旦松，她能动的东西就不是"一个签名"了 |
| 4 | **多一层 = 多一类 bug** | 今天四个 bug **全是"多一层"引起的**（`this` 丢失、字段错位、接口不存在、返回形状），而且都属于"自测全绿、真机才炸"。加一层协同，这类 bug 会再来 |
| 5 | **谎话不会自动消失** | 它只是从"她说她做了"变成"她转述外援的结果"。**汇报那一环是新的说谎点** → 必须"原文附上"，不能只让她用自己的话讲 |
| 6 | **成本** | 每次派活有 **2 万 token 量级**的固定开销（项目记忆文件会被带进去）。**小事派出去不划算** —— 点赞/投币/签名这种，现在的代码直连更快更准 |

## 四、「不动」的代价（也得摊开讲）

- 每加一件新本事 = **我写代码 + 你重启**（今天你重启了四次，全是我 bug 逼的）。
- **永远做不了**多步/联网/写脚本/看屏幕这类活 —— 因为每件都得我先写死。
- 桌宠只是个动画，**没有"她真在干活"可演**。
- 但好处也真实：**链条短、故障点少、内存占用小**。你现在这套在"聊天陪伴 + 偶尔改个签名"这个范围内是够用的。

## 五、我的建议：**分档起步，别一次到位**

### 档 0：影子模式（半天，零风险）—— 我最推荐先做这个

她照常回答，但**同时在后台把同一件事派给 agent 跑一遍**，结果只记进日志、**不采纳**。
跑一两天你就能看到：外援到底能不能干好、平均多久、吃多少内存、有没有胡说。
**行为一点不变** —— 看完数据再决定要不要真接上。

### 档 A：只读外援（半天~1 天，低风险）

明确说「干活：…」才转包，而且**只允许查/看/读/总结**这类**只读**任务（查资料、看屏幕、读文件、整理）。
不写文件、不跑命令。体验提升明显，风险最低。

### 档 B：完整外援（1~2 天）

在档 A 上开写权限，限定**工作目录**，动系统/装东西必须你点头。
配套：结果原文落盘（`logs/agent-jobs.log`）、一次只跑一件、跑前报可用内存、超时 15 分钟。

### 档 C：桌宠 + 语音 + 陪玩

`dsh-pet` 打开（改一行配置 + 重启 DSH，10 分钟）；之后才是读屏幕陪玩、语音（要装 ASR）。

## 六、一句话决策

- **只想要"聊天陪伴 + 她有自己的生活（说说/签名）"** → **别动**，保持现在这套薄的，把可靠性继续磨。
- **想要"能干活、能陪玩、桌宠不是摆设"** → **动，但从档 0（影子模式）开始**，看两天数据再往上加。
- **不管选哪个**：签名/昵称/说说"她自己决定时机、你只审批"这条**已经上线**了，跟这个决策无关。

## 附：今天已经踩过的坑（说明我在防什么）

| 坑 | 教训 |
| --- | --- |
| 把 `onebot.call` 摘下来用，丢了 `this` | 账号动作**执行即崩**，自测还全绿（替身形状和真身不一样） |
| 拿"昵称"的值写进"签名"字段 | 请求和字段必须**逐一对应**，认不出就问，别猜 |
| 以为 `get_qq_profile` 能用 | 真机**根本没这个接口**（回 1404）—— 假设必须真调一次才算数 |
| 接口报成功就报成功 | 昵称实际**没变**（回读 12 秒不变）→ 凡写操作**必须回读验证** |
| 谎话闸判据只认"那个词" | 它说「改上去了」「发了发了」就漏了 → **判据要认"这类断言"** |
