# qq-bot

一个跑在本机的 QQ AI 聊天机器人。**零运行时依赖**（只用 Node 内置能力，不需要 `npm install`）。

- 协议端：[NapCat](https://github.com/NapNeko/NapCatQQ)（把 QQ 客户端接出来，暴露 OneBot 11 接口）
- 模型后端：DeepSeek API / 本地 Ollama，改一行配置就能切
- 行为：私聊全回；群里只有 @ 它才回

> ⚠️ **先说风险**：NapCat 是第三方项目，未经腾讯授权，属于灰色地带。用它跑机器人**有账号被风控的可能**。
> 所以默认建议**用小号**，不要用绑了支付和大量好友的主号。频率限制、白名单这些不是可选项，是保险。

---

## 它长什么样

```
QQ 客户端 ──注入──> NapCat 协议端 ──OneBot 11 WebSocket──> bot.mjs ──> DeepSeek / Ollama
     ^                                                        │
     └──────────────── send_private_msg / send_group_msg ──────┘
```

代码分成两层，**切后端只动一层**：

| 文件 | 职责 | 换后端要改吗 |
| --- | --- | --- |
| `src/onebot.mjs` | OneBot 11 协议：连接、重连、事件解析、发消息 | 换掉这一个文件 |
| `src/router.mjs` | 触发规则：私聊/群聊、@ 判定、白名单、冷却 | 不用 |
| `src/session.mjs` | 多轮上下文、过期清理 | 不用 |
| `src/llm.mjs` | 模型后端抽象（deepseek / ollama / echo） | 换个 provider 名 |
| `bot.mjs` | 编排 + 命令行 | 不用 |

## 自测（不需要 QQ、不需要 API Key）

```powershell
node tools/selftest.mjs
```

它会起一个 OneBot 11 协议端替身（`tools/mock-onebot.mjs`），用 `echo` 模型把整条链路跑一遍，
并断言：私聊会回、群里没 @ 不回、群里 @ 了会回、上下文记住了上一轮、白名单拦得住。

**为什么要有这个**：它把"平台侧的问题"和"我自己的代码问题"隔开了。以后机器人不回话，
先跑自测——自测过了就说明问题在 NapCat 或账号那边，不用两头猜。

## 改 config.json 的血泪纪律（我真的栽了三次）

**`llm.system` 是一整行 JSON 字符串，里面绝对不能出现未转义的半角双引号 `"`。**
一出现，整个 config.json 解析失败、机器人起不来。

同一个坑本项目栽了**三次**，都是写中文时顺手打了 `"`：

| 我写的 | 结果 |
| --- | --- |
| `（"怎么了""说吧"）` | JSON 在第一个 `"` 处被截断 |
| `让你"说"、"念"` | 同上 |
| `也别因为"气氛到了"就发` | 同上 |

**规则：中文里要引号一律用 `「」` 或 `『』`，永远不用 `"`。**

自测第一步就是解析配置，所以**改完立刻跑 `node tools/selftest.mjs`** 就能秒级暴露；
另外可以用这段一次性查全仓：

```powershell
Get-ChildItem -Recurse -Include *.json | Where-Object { $_.FullName -notmatch 'node_modules' } |
  ForEach-Object { try { Get-Content $_.FullName -Raw -Encoding UTF8 | ConvertFrom-Json | Out-Null }
                   catch { "❌ $($_.Name)" } }
```

## 停止与重启（这里有个坑）

**DSH 的 `job_kill` 只终止 pwsh 外壳，不会杀掉后台任务里的 node 子进程。**
所以"重启机器人"不能只停任务，必须按 PID 停：

```powershell
netstat -ano | findstr :3001          # 谁连着 OneBot（NapCat 自己也会出现，别杀它）
Stop-Process -Id <PID> -Force         # 停掉机器人那个 node
```

**忘记这么做会攒出多个僵尸实例，同一条消息被回复多次**（实测过一次攒到 5 个）。

`bot.mjs` 现在带**单实例锁**：`logs/bot.lock` 记录 PID，启动时用 `process.kill(pid, 0)`
探活。已经有实例在跑时，第二个实例会**明确拒绝启动并打印要停哪个 PID**，不会静默地变成双份回复。

## 控制面板（推荐用它改配置）

```powershell
node tools/panel-server.mjs
```

然后浏览器打开 **http://127.0.0.1:6182/**

面板里能改：状态查看、人格、模型后端与温度、**DeepSeek 密钥**、触发方式、冷却与上下文轮数、
私聊/群白名单、表情包上传与删除。

**改完即时生效，不用重启**——机器人用 `fs.watchFile` 盯着 `config.json`，
文件一变就原地更新内部状态（router 与 llm 持有的是同一个对象引用）。
日志里会打一行 `配置已热重载：…` 作为证据。

两个刻意的安全边界：

1. **只监听 `127.0.0.1`**，外部连不上。
2. **API 密钥只进不出**：可以写、可以看到「配没配、从哪读的」，
   但任何接口都不会把已保存的密钥读回来，面板上也不显示。

写盘用「先写临时文件再改名」，避免机器人读到写了一半的配置；
万一配置真的写坏了，`reload()` 会保留旧配置继续跑并记一条 error，不会把机器人弄挂。

## 配置

`config.json` **只需要写你要覆盖的项**，其余全部取 `src/config.mjs` 里的 `DEFAULTS`。
完整可抄的模板见 `config.example.json`。

### 一、接大模型

`llm.provider` 决定用哪个后端：`deepseek` | `ollama` | `echo`。**换后端不改一行代码**，
`src/llm.mjs` 里三个后端实现同一个 `chat()` 接口。

DeepSeek 的密钥有两种给法，**两种都不需要重启机器人**（每次请求都重读）：

```powershell
# 方式一：环境变量（推荐）
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "sk-你的密钥", "User")
```

```powershell
# 方式二：写进文件，一行，不要引号
# 文件路径：qq-bot\.deepseek-key   （已在 .gitignore 里）
Set-Content -Path .deepseek-key -Value "sk-你的密钥" -NoNewline
```

设完用 `node bot.mjs --check` 验证。它会明确告诉你是**从环境变量读到的**、**从文件读到的**、
还是**没配置**——但永远不会回显密钥内容本身。

切到本地 Ollama：

```powershell
ollama pull qwen3:8b
$env:BOT_PROVIDER = "ollama"   # 或直接改 config.json 里的 llm.provider
```

### 二、白名单

```json
"whitelist": {
  "users": ["10000000"],
  "groups": []
}
```

规则是**按场景各自生效**：

| 写法 | 含义 |
| --- | --- |
| `users: []` | 私聊**不限制**，谁发都回 |
| `users: ["123"]` | 私聊**只理** 123，其他人的消息直接忽略 |
| `groups: []` | 群聊不限制（仍受 `trigger.group` 的 @ 限制） |
| `groups: ["456"]` | 群聊只理 456 这个群 |

> 早期版本这里是个全局开关 `enabled`，一打开会把**所有群**也一起封掉，跟"群里被 @ 才回"
> 打架，所以改成了按场景独立。`tools/selftest.mjs` 里有 4 条测试专门钉住这个语义。

### 三、人格

`llm.system` 就是这个机器人的性格设定，直接写自然语言：

```json
"system": "你叫小笛，是 QQ 上的聊天搭子。说话简短、口语化，像朋友发消息那样，一般两三句就够。不要用 Markdown、不要列条目、不要说「作为 AI」。拿不准的事直说不知道，别编。"
```

几个经验性的写法：

- **写"不要什么"比写"要什么"管用**。QQ 里最毁体验的是 Markdown（`**加粗**` 会原样显示成星号）
  和长篇分点回答，这两条一定要明确禁掉。
- **给名字和关系**（"你叫小笛，是聊天搭子"）比抽象形容词（"要幽默"）稳定得多。
- **加上"不知道就说不知道"**，否则它会为了圆场编内容。
- 想换风格只改这一句，不用动任何代码。

#### 嘴硬频率：写进代码，不写进提示词

```json
"tone": { "bratEveryN": 3 }   // 每 3 轮放行 1 轮可以嘴硬；0 = 从不
```

> **为什么不交给提示词。** 实测过两次极端：写「大概每三四条回复出现一次嘴臭」，
> 模型会连着好几条都嘴臭；改写成「没把握就别嘴臭」，它又变成**一条都不嘴臭**（7 条 0 次）。
> **模型不会数数。**
>
> 所以频率改由 `src/addressing.mjs` 的 `createTonePicker` 决定：每轮在 system 末尾
> 追加一行【本轮语气】告诉它这条能不能嘴硬，模型只负责执行"这一条用什么语气"——
> 那是它擅长的。**这是确定性的、可断言的**：`bratEveryN=3` 严格产出「臭好好臭好好臭」，
> 自测里 4 条断言钉住 0/1/2/3 各种取值。实测 8 轮：程序计划放行 3 次、实际嘴臭 2 次、
> **连着 0 次**。

另外几条踩出来的经验：

- **「凶只是皮、底下完全听话」必须写清楚**。否则"傲娇"会被模型当成可以推脱、拖延、
  讨价还价的许可。要明确写「**嘴上可以损，手上必须马上办完**」。
- **让它干活要防一个坑**：说「把 X 翻译成英文」，它会去翻译「帮我翻译」这句指令本身。
  要写明「**要处理的是他给你的那段内容，不是这句指令本身**」。

#### 结尾那个「~」（嘴硬的时候）

嘴硬的那一轮，**整条回复的最后一句句末会变成 `~`**（「杂鱼主人真是的~」那种尾音）。

```json
"tone": { "bratEveryN": 3, "bratTilde": true }
```

这也写在代码里（`src/style.mjs` 的 `bratTilde`），不是提示词——标点这种东西模型做不稳定。
**触发条件是「这一轮在不在嘴硬」，不是「文本里有没有杂鱼」**：排期本来就由代码定
（`createTonePicker` 每轮返回 `{ mayBrat, hint }`），所以直接拿这个判断，不用去猜文本。

细节：只动**结尾那一句**（不逐句加，避免满屏 `~`）；句末本来是 `。！？，` 就替换、
本来没标点就追加；已经有 `~`/`～` 就不动；不动换行、不碰行尾空白。

> ⚠️ **一个取舍**：判定用的是「排期放行 **或** 文本里确实出现嘴硬词」。
> 所以如果某一轮排期放行、但模型自己选择温柔说话，它**仍会**带上 `~`
> （实测过：「有事喊我，我不走的~」）。这是故意的——宁可偶尔多一个波浪号，
> 也不要该带的时候漏掉。想改成严格按文本判断，把 `bratty` 的来源换成
> 只取 `looksBratty(reply)` 即可。

#### 结尾那个「喵」

温柔 / 关心 / 安慰 / 撒娇 / 道别的时候，最后一句句尾带一个「喵」。写在两处：

1. 人格里给**规则和例子**：一条最多一个、放最后一句、嘴硬时绝对不带、报数据时可以不带。
2. 每轮语气提示里给**强制条件**（`src/addressing.mjs`）：温和轮且属于上述场景时
   写「**必须**带一个」；嘴硬轮写「**这一条不要带**」。

> 一开始温和轮写的是「**可以**带」，实测只中 3/8——「被老板骂了」这种明显该带喵的场景
> 反而漏了。改成「**必须**」之后到 4/5。**"可以"和"必须"的差别很大，写提示词时别含糊。**
>
> 实测 9 轮：温柔场景 5 个中带喵 4 个；**喵出现在嘴硬轮 0 次**；**一条里多个喵 0 次**。
>
> （小笛是鲸鱼娘，加猫叫是有反差萌的，所以人格里顺手把这件事圆过去了：
> 「鲸鱼也会喵，不许质疑，这是常识」。）

### 三·五、玩梗与梗库

改 `llm.system` 里的【玩梗】那节 + 编辑 `memes.md`。

**先搞清楚是哪种"不会玩梗"**——两种原因，修法完全相反：

| 症状 | 怎么判断 | 修法 |
| --- | --- | --- |
| **不认识梗**（知识问题） | 直接问它某个梗什么意思 | 给梗库 |
| **认识但不用**（行为问题） | 问它认识、聊天时却不接 | **改提示词 + 给具体清单** |

实测这台的情况是**第二种**：不带人格地问 12 个当前热梗，**它全答对、解释也对**，
但真聊天时一个都不用。所以"给知识"没用——缺的是**用法和许可**。

#### 踩坑：禁止性措辞会压过许可性措辞

第一版写了「该用就用」，同时写了「别硬凑」「硬塞比不玩更尴尬」——
结果**一个梗都不用了**。模型遇到模糊就往禁止那边倒。

**这已经是本项目第二次栽在同一件事上**：上一次是嘴臭频率，写「没把握就别嘴臭」，
它直接变成 0 条。**结论：光写"你可以 X"斗不过"别 X"。**

#### 有效的那一招：给它一份具体清单

`memes.md` 里的内容会（清洗后）整份接进 system。实测同样的 7 个场景：

| | 用上真网络梗的回复 |
| --- | --- |
| 加梗库之前 | **0/5** |
| 加梗库之后 | **4/7**（那咋了 / 主打一个 / 有一说一 ×2） |

而且没硬凑——另外 3 条本来就不需要梗，就没用。「别硬凑」那条守住了。

**为什么清单比"教它玩梗"有用**：模型对"从这份清单里挑一个用"的执行力，
远高于"你自己想想有什么梗"。

#### 梗库最不可替代的价值：群内梗

网络热梗它本来就认识。**群里自己的黑话、外号、内部典故，它无论如何也推不出来**——
只有你能告诉它。面板上有个梗库输入框，改完保存，**下一条消息就生效，不用重启**。

> ⚠️ **清洗是必须的**。`memes.md` 里带着给人看的说明和示例，整份塞进 prompt 的话，
> 模型会把**示例当成真梗来用**（差点就让它去用"老张的保温杯"了）。
> 所以 `cleanMemes` 会去掉 `#` 注释行、空行、以及 ``` 代码块。

#### "真正理解"和"文字对照"的区别

一开始梗库只有 **梗词**（`那咋了 —— 摆烂式反问`）。这类只有"认识"是不够的，
因为**光认识它不会在正确的时刻想起来用**。所以加了第二类：**场景梗**。

场景梗按 **话题 → 梗** 写，不是按字面对应：

```
有人说自己喜欢萝莉／年纪小的／初中的小孩／"体型小的"，而且说的不是你
  —— 用「电一电」回敬：「你是想挨电了是吧，要南方电网还是北方电网」
  机制是拿杨永信电击治疗那段黑历史开玩笑……
  分场合：如果对方只是在夸你小只可爱（说的就是你），顺着撒个娇就行，别电他。
```

**实测它确实能泛化**（这才是"理解"的证据）：

| 群友说 | 结果 |
| --- | --- |
| 我就喜欢体型小的，萝莉那种 | 「你是想挨电了是吧，要南方电网还是北方电网。」 |
| 我觉得初中的小孩挺可爱的 | 先问"是单纯觉得可爱还是别的意思"，再「那可真得电一电了」 |
| 我比较喜欢年纪小的女生 | **先反问**"你是指年龄小的女生聊得来，还是别的意思"——这句本身有歧义，问清楚是对的 |
| 小笛你好小只好可爱啊 | **没电**，改成害羞收下夸奖 —— 分场合那条生效了 |

**只写了一条场景梗，换三种说法都认得出，而且说的是它自己时就不电。**
关键在于写**机制**（为什么这个梗好笑），而不只是写"遇到 X 就回 Y"——
有机制它才能处理歧义和变体。

> ⚠️ **"让它自己上网找恰当的梗"这条路对这类话题不可靠**，我没有采用：
> 搜"萝莉 梗"返回的很可能是不该发给你的东西，而且本项目的 Bing 梗搜索结果
> 一直是垃圾（`.md` 里记了实测）。网络搜索适合查"某个具体的梗是什么意思"，
> 不适合"这个场合该用什么梗"。后者只能靠你把关联告诉它。

#### 字面玩梗：把字变成表情

有一类梗跟"认识某个梗词"无关，是**字面意思的视觉化**：

| 对方发 | 它回 |
| --- | --- |
| 冰冰冰 | 🧊🧊🧊 |
| 火火火火 | 🔥🔥🔥🔥 |
| 钱钱钱钱钱 | 💰💰💰💰💰 |
| 猫猫猫 | 🐱🐱🐱 |
| 哈哈哈哈哈 | 😂😂😂😂😂 |
| 饿饿 | 🍚🍚 |

规则写在 `llm.system` 的【字面玩梗】一节，关键是**数量必须跟对方一致**
（他说三个冰你回三个冰块，别回两个）——这条模型执行得很好，实测 **6/6 全对、数量全准**。

> **改之前它完全不会这个**：「冰冰冰」被它当成没说完的半句话
> （"冰什么冰，你又没把话说完"）。所以这不是知识问题，是**没被要求过**。

想加自己的模式（比如你们群里约定某个字对应某个表情），
直接往【字面玩梗】那节的例子列表里加一行就行，或者写进梗库。

#### 不懂的梗就让它去搜

`llm.system` 的【不懂的梗就去搜】要求它：遇到没见过的网络梗/流行说法，
**先 web_search 搜「XXX 是什么梗」，别装懂也别硬接**。

关键是**加了"最多搜两次"这个上限**。实测：

- 「冬瓜炖西瓜」（编造的，网上没有）→ 搜两次 → **老实说"我没查到"** ✅ 没编
- 「电子包浆」（真实存在）→ Bing 老返回字典页 → 搜两次 → **改用自己知道的知识答对了** ✅

> **不加"最多两次"会出事**：一开始它连搜 4 轮，把轮数用完，用户收到
> **「（工具调用轮数用完了，没得出结论）」——一句内部错误信息**。

#### 工具轮数用完时的兜底

`createToolChat` 在轮数耗尽后**不是直接把状态抛给用户**，而是**再问一次、这次不带工具**，
并在 system 末尾加一句「只根据已有信息回答，不要再请求工具」。
把"失败"降级成"能答多少答多少"。

自测里 3 条断言钉住它：会再问一次、那次不提供工具、system 里带了那句提示。

### 四、让它会发图

模型没法凭空产出图片，所以这里是**点单式发图**：本地 `stickers/` 里的**文件名就是标签**，
prompt 会把可用标签告诉模型，它想发图时在回复里写 `[[图:开心]]`，
程序把标记换成真实图片段发出去（文本和图片在同一条消息里）。

```
stickers/
├── 开心.png          → 标签「开心」
├── 大笑-1.png        → 标签「大笑」
├── 大笑-2.png        → 也是「大笑」，发的时候随机挑一张
└── 摸摸头.png        → 标签「摸摸头」
```

跑 `python tools/make-stickers.py` 会生成一套 10 张的起步文字表情包（零版权风险）。
换真人表情包直接覆盖同名文件即可。

**在控制面板里可以直接上传，也支持整个 zip 压缩包批量导入。**
压缩包内可以带子目录（会取 basename）、非图片文件自动跳过、macOS 的 `__MACOSX/._*` 垃圾
自动忽略、**重名自动加序号而不会覆盖你已有的表情包**。

zip 是**自己解的**（`src/zip.mjs`），没走外部命令：Node 没有内置 zip 解析，而调用
PowerShell 的 `Expand-Archive` 在 DSH 沙箱下会因为命名管道被拒而 `EPERM`。
自己实现还带来两个好处——可以精确限制张数与单张体积，而且**压缩包里的路径穿越
（`../../x.png`）会被压成 basename**，写不出 `stickers/` 目录。

**设计上的两个关键取舍：**

1. **让模型"点单"而不是"生成"**。生成图片要么慢、要么不可控、要么得再接一个图像 API。
   点单的失败模式是良性的——它不可能发出库里没有的东西。
2. **未知标签静默丢弃**。模型偶尔会点一个不存在的标签，这时候**只丢掉那个标记，
   正文照发**，日志里留一条 warn。绝不能因为一张表情包把整句话都弄没了。
   同理，图片发送失败时会自动**退回纯文本重发**。

### 四·五、让它能看懂图（2026-10-07 新增）

**能力**：用户在私聊或群里发图，它**真的看图**，而不是只看到「[图片]」三个字。

**实现**：`router.mjs` 的 `extractImages()` 把 image 段解析出来（array 与 CQ 码两种格式都吃）；
`bot.mjs` 的 `describeImages()` 把图下载成 base64，交给 `llm.mjs` 里**已有的** `askWithImage()`，
拿回一段中文描述，拼成 `【图里的内容】…` 追加到这一轮的用户消息。

**几个刻意的设计**：

- **不装任何本地视觉模型**。DeepSeek 的 chat API 虽然只宣传文本，但传 `image_url`（data: URL）
  能正确识图——实测三张不同的图能分别读出对应文字。
- **用「转文字」而不是多模态消息**：`chat()` 是纯文本接口，改它要动整条工具调用链；
  而转成文字能一并写进会话历史，**下一轮它还记得图里有什么**。
- **`text` 里的「[图片]」占位符保留**，它标明「原文这个位置有一张图」
  （多图时区分「哪张」要用到位置信息）。
- **只发图不配字也会理**。以前 `if (!text) return` 会把这种消息整条丢掉。
- 读图失败**不会让整轮失败**，只会退化成「（有一张图没读出来：…）」。

**代价**：每张图多一次 API 调用（一张 240×240 约 190 prompt token），
所以默认每轮最多读 `vision.maxImages` 张。

```json
"vision": { "maxImages": 2, "identifyAnime": true }
```

#### 认角色（动漫截图溯源）

同一张图还会**并行**送给 [trace.moe](https://trace.moe)：免费、免 key 的动画截图检索，
返回「出自哪部动画、第几集、第几秒、相似度」。结果拼成
`【以图搜图】疑似出自《…》第 4 集 5:20 附近…` 追加在描述后面。

**它只对动漫截图有效** —— 照片、表情包、游戏 CG、真人图返回空，那是正常的，不是失败。

⚠️ **必须防误报**：实测一张 **264 字节**的图被它判成某动画第 11 集「相似度 100.0%」——
画面特征太少时它会给出荒谬的高分。所以 `src/imagesearch.mjs` 里有 `MIN_TRACE_BYTES = 4KB`，
小于这个尺寸**在发请求之前**就挡掉；相似度阈值另设 0.82。

#### 抖音链接：拿不到，此路不通

实测（2026-10-07）：**未登录状态下抖音对任何路径都返回同一个空壳** ——

```
https://www.douyin.com/                          → 200，72914 字节，<body></body>，只剩混淆 JS
https://www.douyin.com/video/7300000000000000000 → 200，**完全相同的 72914 字节**
```

第二行的 video id 是**编的**，它照样返回同样内容 —— 说明服务端不区分路径、统一发空壳。
所以「抖音链接打不开」不是代码问题，是**不登录就拿不到内容**。
别再在这上面花时间：遇到抖音链接就直说打不开，让用户贴文字或换 B站。

### 四·六、让它真的「看」B站视频（2026-10-07 新增）

**关键发现：不需要语音识别 —— 登录就能拿字幕。**

实测（2026-10-07）：

| 途径 | 未登录 | 登录后 |
| --- | --- | --- |
| `player/v2` 的字幕列表 | **恒为空** | 有（AI 字幕 / CC 字幕） |
| `view/conclusion/get`（官方 AI 总结） | `code=-403 访问权限不足` | 可用 |
| 音频流 | 能拿（但要补 `origin` 头） | 能拿 |
| 弹幕 / 简介 | 能拿 | 能拿 |

所以「视频里说了什么」用**字幕**解决：字幕是 B站自己对齐好的逐句文本，
**比语音识别更准、更快、而且不用装任何东西**（省掉了本地方案那 228 MB 的模型）。

**怎么开**（三种都行，任选）：

1. **用控制面板（推荐）**：`http://127.0.0.1:6182/` → 「模型与密钥」→ **B站登录** 卡片 →
   粘贴 `SESSDATA` → 保存。**只写不读**：面板不会回显内容，只显示「已配置 + 来源 + 多少字符」。
2. 手动写进仓库根目录的 `bili-cookie.txt`（第一行非 `#` 的内容就是它）。
3. 设环境变量 `BILI_SESSDATA`（**优先级最高**）。

`SESSDATA` 怎么拿：浏览器登录 bilibili.com → `F12` → `Application` → `Cookies` →
`https://www.bilibili.com` → 找到 `SESSDATA` → 复制它的 **Value**。

- ⚠️ **这是登录凭证**，等价于账号登录态：不要提交、不要外传，也**不会写进记忆文件**。
- ⚠️ **在浏览器里点「退出登录」会让它立刻失效**（那正是「退出」在干的事）。
  想让它长期可用，**就别退小号的登录**；失效了回来重新粘一次即可。
  关掉浏览器、清缓存通常不影响；时间长了也会自然过期。
- **填完立刻生效，不用重启** —— `readSessData()` 每次调用都重读文件。

#### ⚠️ 这个接口本身不可靠：会串号

2026-10-07 实测，`player/v2` 的表现是：

- 同一请求连打，**有时返回 12 条字幕、有时 1 条、有时 0 条**；
- **大多数时候 `subtitle_url` 是空的**（8 次里 7 次）；
- 最危险的是它**偶发返回别的视频的字幕** —— 实测两次撞上：
  点进去是 Rick Astley 的英文歌，字幕却是「杨幂回旋镖」和「帕尼尼减肥法」。

所以最终做了三层防护：

1. **补设备指纹**（`buvid3`/`buvid4`，从 `x/frontend/finger/spi` 自取，**不需要用户提供**）——
   只带 SESSDATA 时成功率极低，补上后明显改善；
2. **同一个请求最多打 6 次，按字幕 URL 的指纹投票**；
3. **只接受拿到 ≥2 票的候选** —— 单票很可能就是串号。

实测结果：**6 次里 5 次拿到正确字幕、1 次明确返回「没拿到」，零错误内容。**
准确率优先于覆盖率 —— 对陪伴型机器人来说，**说错比说不出更糟**。

#### 「画面」也能看一点：进度条缩略图

**2026-10-07 新增。** B站 的 `player/videoshot` 直接返回一张**雪碧图**：
默认 10×10 = 100 格、每格 160×90、相邻两格约隔 5 秒。把整张图交给视觉模型，
它真能说出画面内容 —— 实测对那支 Rick Astley 的 MV 给出的是
「复古歌舞片、多人、有麦克风和餐桌、镜头在特写与全景间跳切」，与实际吻合。

**成本**：一张图约 60 KB、约 950 prompt token。**不需要 ffmpeg、不需要下载视频、不用登录。**

⚠️ **局限**：每格只有 160×90，所以只能看**场景 / 人物 / 大致变化**，
看不出细节动作、也看不清画面里的文字。要细节还得回到抽帧那条路（那才需要 ffmpeg）。

配置：`"bilibili": { "describeFrames": true }` —— 关掉就只给字幕。

> **一个值得记下的判断失误**：我此前说「看不到画面」，依据是「下载视频 → ffmpeg 抽帧」
> 这条标准路径 —— 而它在你这台机器上**确实走不通**（没有 ffmpeg）。
> 但「这条路走不通」不等于「这件事做不到」：B站 自己就提供了一张覆盖全片的缩略图网格。
> 我差点把一个**我没想到**说成了**不可能**。

**链接会被自动点开**（2026-10-07 新增）：消息里出现 B站 / `b23.tv` 链接时，
**代码直接调 `bilibili_video`，把结果塞进这一轮的上下文**，不等模型自己决定。

> 为什么必须这样：实测模型**不会**主动调这个工具。用户发
> 「【视频标题】 https://b23.tv/xxx」，它拿消息里**现成的标题**就答了，
> **1450ms 就回完**，还替自己编了句「短链不给内容」—— 而那条短链实测 302 就指向
> `BV1T1te6mEF2`，工具跑出来连弹幕和画面都有。
>
> **同一个毛病在这个项目上已经出现三次**（读图、读链接、「只发图不配字被丢弃」）。
> 凡是「希望它一定会做」的事，**一律用代码兜**；提示词只负责「怎么做得好」。

配置：`"bilibili": { "autoReadLinks": true }`（关掉就只剩模型自主决定）。

**拿不到字幕时**（未登录 / UP 主没开 / 接口这次不稳），工具会明确告诉模型
「**不要猜视频内容**」—— 这比让它对着一个标题编一段要安全得多。

**顺带修的两个问题**：

- `bilibili_video` 以前只认 BV 号，**`b23.tv` 短链和 `av` 号都会失败**
  （用户看到的就是「为啥必须给 BV 号」）。现在 `resolveBvid()` 四种都认：
  短链跟一次重定向、`av` 号查一次接口转换。
- **音频下载本来全部超时**，补上 `origin: https://www.bilibili.com` 之后三个 CDN 全部 206。
  有些站点缺一个请求头就整个连不上，**别急着换方案**。

### 五、主动开口（长时间没消息时自己来找你）

```json
"proactive": {
  "enabled": true,
  "afterMinutes": 180,     // 安静多久才考虑开口
  "minGapMinutes": 240,    // 两次之间至少隔多久
  "maxPerDay": 2,          // 每天最多几次
  "groups": false,         // 群里是否也主动开口（默认不）
  "quietHours": { "from": 23, "to": 8 }   // 免打扰，本地时间，可跨午夜
}
```

> ⚠️ **这项默认是关的，而且我建议保持保守。** 平台把「没人叫它却自己发消息」
> 看作典型机器人行为——主动消息比被动回复更容易触发风控。
> 免打扰时段别删，半夜三点鲸鱼娘来找你不是可爱是灾难。

实现要点：

- 决策逻辑在 `src/proactive.mjs`，是**纯函数**（`shouldPing`），所以"该不该发"不用真等三小时就能测——
  自测里有 15 条覆盖空闲阈值、重复抑制、每日上限、跨午夜的免打扰。
- 只能对**发生过对话的人**开口（会话表里没有的人不会被打扰）。
- 开口内容由模型生成，用「在当前 system 后追加一段任务说明」的方式驱动，
  **而不是伪造一条用户消息**——后者会污染上下文，让模型以为对方真的说过那句话。
- 它自己开口说的话会被记进上下文，所以下一轮它知道"我刚才说过什么"。
- 面板上有「**立刻试一次**」按钮：往 `logs/ping-now` 写个文件，机器人下一轮轮询就强制跑一次，
  不用等三小时。注意轮询是 60 秒一次，而且**得先有过对话**才有人可发。

#### 「把主人当恋人」（只影响对主人）

```json
"master": { "users": ["10000000"], "title": "主人", "romantic": true }
```

面板上「触发与白名单」里有个勾选框。开启后**只有名单里的人**会拿到这段设定——
它是挂在 `composeAddressing` 里的，而那里本来就**按每条消息的发送者**决定注入什么，
所以**对别人一个字都不会变**（这正是"不冲突"的实现方式）。

设计上刻意做成**叠加**而不是另起一套人格：

- 傲娇 / 嘴硬排期 / 喵 / 拆段那些规矩**照旧**；
- 恋人设定只改写它们的**含义**——「嘴硬 = 我其实很高兴」而不是「烦你」；
- 明确写了**不写性描写**，甜而不腻。

实测（同一个人、同一句话，只切开关）：

| 输入 | 恋人关 | 恋人开 |
| --- | --- | --- |
| 你想我了吗 | 「才、才没有呢，谁想你了，杂鱼主人。」 | 「才不想呢，杂鱼主人。……**好吧，有一点点想。就一点点。**」 |
| 我去找别人聊天了 | 「哦，去呗，我又没拦着你。」 | 「哦。去吧。**……才怪。你聊归聊，别聊太久啊。**」 |
| 我今天好累啊 | 「累了就歇会儿，别硬撑。」 | 「怎么啦，干什么了这么累。瘫那儿歇会儿吧，**我陪着**。喵～」 |

**原有的东西一条没丢**，只是底下多了在意。

`DEFAULTS` 里这个开关默认 **`false`** —— 新克隆一份配置不该自带恋爱关系。

### 六、谁能被叫「主人」
```json
"master": { "users": ["10000000"], "title": "主人" }
```

**称呼是跟人绑定的，所以不能写死在人格里**——人格是全局的，写死的话群里所有人都会变成主人。
实现上按**每条消息的发送者**动态拼一段 `【当前对话对象】` 追加到 system 后面：

```
【当前对话对象】QQ 10000000（主人） —— 这就是你的主人，称呼他「主人」。
【当前对话对象】QQ 999 —— 这是**别人，不是你的主人**。绝对不要叫他「主人」，
用「你」称呼就好；态度可以友好，但别撒娇、别用对主人那套语气。
```

判定逻辑在 `src/addressing.mjs`，是**纯函数**——所以"别人会不会被叫主人"不用拉个群试，
自测里 7 条覆盖了主人本人 / 陌生人 / 群聊无具体对象 / 名单为空 / 原 system 保留。

顺带：人格里我保留了一句「谁是主人、该怎么称呼，程序会在每条消息里告诉你，**以那条为准**」，
把优先级写清楚，免得两处冲突。

### 七、自动给表情包打标签（视觉模型）

网上下的表情包文件名通常是 `IMG_2831.png` 这种，模型没法据此选图。跑一次：

```powershell
node tools/tag-stickers.mjs            # 只处理还没标签的
node tools/tag-stickers.mjs --force    # 全部重新识别
node tools/tag-stickers.mjs --dry      # 只看结果，不写文件
```

结果写进 `stickers/tags.json`（`{ "IMG_2831.png": "大笑" }`）。

**改错的标签在面板上点图片左上角的 ✎ 直接改**（1–6 个字，标点会被自动剥掉；
**留空 = 撤销手改**，退回自动识别）。手改的标签**不写进 `tags.json`**，
而是单独存 `stickers/tags.manual.json`，读取时手动那份优先：

```
stickers/tags.json          ← 视觉模型产出，跑 --force 会整份重写
stickers/tags.manual.json   ← 你手改的，任何脚本都不会碰它
```

**为什么分两份**：如果手改的也写进 `tags.json`，那么下次点「全部重新识别」
你辛苦修的几个词就被冲掉了。分开放之后 `--force` 只重写它自己那份，手改的永远生效。

**改写的是标签映射，不改你的文件名**——文件名是你的，标签是推导出来的，覆盖掉不可逆。
删掉这两份 json 就完全回到「用文件名当标签」的行为。

> **实测结论：不需要额外装本地视觉模型。** DeepSeek 的 chat API 虽然对外只宣传文本，
> 但传 `image_url`（data: URL）能**正确识别图片内容**。三条独立证据：
> 三张不同的图能分别读出对应文字且 `prompt_tokens` 完全相同（说明不是从文件名蹭的）、
> 能答出背景色与圆角形状、1×1 纯色图会被如实描述成「纯色、没有图案」。
> 成本也低：一张 240×240 的图约占 **190 个 prompt token**。
>
> 所以 Ollama 不是必需品。它在 `llm.provider` 里留着，是给「不想把图片发到云端」的场景。

模型输出会被 `cleanTag()` 洗一遍（剥标点引号、只取第一个词、限长 6 字），
**不合格就丢弃、保留原样**——宁可不标，也别标错。它回一个问号表示拿不准，同样丢弃。

实测一套 358 张的真实表情包：**343 张识别成功、3 张拿不准、12 张失败**，
收敛出 **93 个有意义的中文情绪标签**（`你已急哭`、`炫我嘴里`、`疯狂星期四`、`摆烂`…）。
失败的那十几张会继续用文件名当标签，不影响使用。

> **表情包目录是会变的，所以机器人会重扫。** 目录 mtime 一变就重读并重建 system prompt，
> **不用重启**——日志里会打一行 `表情包库已刷新：…`。
> 没有这一层会出事（真实踩过）：用户把整套表情包换掉，机器人手里还攥着旧文件名，
> 模型照着旧标签点单，读文件时 `ENOENT`，**整条回复崩掉**，用户只收到「我这边出了点问题」。
> 现在读不到的图片会被**就地丢掉、只留文字**，绝不把整句话带崩。

⚠️ prompt 里最多列 200 个标签（`MAX_TAGS_IN_PROMPT`）。**没列出来的标签模型就选不到**，
所以别把这个值调小；真撞到 200 多半说明自动打标签没跑。

### 八、让它真的能做事（工具调用）

纯聊天模型**做不了任何事**——你问天气它只会说查不到。开这个就解决了：

```json
"tools": { "enabled": true, "maxRounds": 4, "enabledTools": [] }
```

现有四个工具，都是**只读、无副作用、不需要密钥**的：

| 工具 | 干什么 | 数据源 |
| --- | --- | --- |
| `get_weather` | 某城市实时天气 + 最多 3 天预报 | [Open-Meteo](https://open-meteo.com)（免费无 key） |
| `get_time` | 当前日期时间（可指定时区） | 本机时钟 |
| `web_search` | 联网搜索，返回标题 + 链接 + 摘要 | Bing（`cn.bing.com/search`，免 key） |
| `fetch_page` | 打开网页读正文（摘要不够时深入看某页） | 目标网页本身 |
| `search_images` | 搜图片，返回图片直链；可让机器人**直接发出来** | Bing 图片搜索（强制 `adlt=strict`） |
| `search_videos` | **只返回搜索页链接**，不给具体视频（原因见下） | B站 / Bing / 抖音 |

#### 发网图：两道卫生闸

模型在回复里写 `[[网图:https://…]]` 就会发那张图，**私聊和群里都发**。
放行条件全在代码里（`src/tools.mjs` 的 `createWebImageGate`，纯函数、可注入、可测）：

1. **必须是本次搜索结果里出现过的地址**。工具模块用一个小集合记住搜出来的图片直链，
   `isSearchedImageUrl` 放行。**模型自己编的、凭记忆写的地址一律不认**——
   没有这道闸，模型可以直接吐任意 URL 让 NapCat 去下载发送。
2. **目标主机不能是内网**。NapCat 会去下载这个 URL，等于让模型指挥本机发请求，
   所以复用 `fetch_page` 那套 `isBlockedHost` 防护。
3. 外加**数量上限** `chat.maxWebImages`（默认 4），防刷屏。

`splitReply` 的 `allowWebImage` **默认一律拒绝**，必须由调用方显式传入——
默认放行是这类设计最容易犯的错。

> **踩过的坑：这段逻辑一开始写死在 `bot.mjs` 里，自测完全覆盖不到。**
> 其中有一条「只私聊发图」，只有在真实群聊里才会触发——结果就真踩了：
> 群里用户要图，机器人回「给你找了四张：」，四张**全被闸门拦掉**，
> 日志里只有一行 warn，用户那边什么都没显示。
> 抽成可注入的纯函数之后，8 条断言把各种组合钉住了（超限、非白名单、内网、
> 畸形 URL、max=0、以及"被拒的不占配额"）。**只在真实场景才会触发的分支，
> 不值得留在调用方内部。**

#### 找图：由代码接管，而且**不许重复发**

「找 X 的图」这句话由 `src/intents.mjs` 的正则接管，`bot.mjs` 的 `findAndSendImages()`
去搜、**自己下载、直接发**（不让模型拼链接——它拼的链接用户点开基本是 403）。

2026-10-07 用户当场抓到「**我的意思你发的图一样**」（说「再来两张」时）。查下来是**两个
各自独立**的原因，缺一个都还会重：

1. **记"发过的图"的字段写错了**：代码写 `refs.sentImages = [...(refs.sentImages ?? []), g.url]`，
   而 `g` 那个对象**只有 `buf`、根本没有 `url` 字段** —— 记进去的全是 `undefined`，
   跨轮排除从来没生效过，于是"追问"把同一批图又发了一遍。不会有报错、不会有日志，
   只有用户看得见。修法：`collectFreshImages()` 返回每张图的**身份键**，代码只记键。
2. **只比地址不够**：同一张图换个图床、换个变换后缀就是另一个地址。实测翻到第 2 页时
   `wiki.42lab.cloud/…/Lpic_hk416_happyzoo.png` 与第 1 页那条**字节完全相同**。
   所以判据是两层——`imageUrlKey()`（归一化地址：去掉 `?x-bce-process=`、`@!18183`、
   `.thumb.1000_0` 这类变换后缀）+ `imageShaKey()`（下载后的内容 sha256）。

拿新候选这件事本身也有坑：**同一个词搜两遍，Bing 返回的是同一批**，
`/images/search` 上 `first` / `count` 参数**完全无效**（实测 first=1 / first=100 / count=50
抽回来的前 6 条与不带参数时 100% 相同）。真正能翻页的是
`/images/async?first=36&mmasync=1`（与首页重叠 0/6）。所以：换词从头搜，同一个词追问就往后翻。

对账入口：日志里 `[找图] 「词」first=1 起、翻 N 页 / M 个候选 → 发出 K 张（sha …）；
跳过发过的 X、下载失败 Y`，以及
`node tools/probe-image-dedup.mjs 可露凯`（真打网络重放两轮，末行必须是`跨轮内容重复：0 张`）。

图片搜索强制 `adlt=strict`。**但实话是**：这个过滤是尽力而为，我没法验证它真的挡住了什么
（要验证就得拿成人内容去试，那正是我不做的事）。真正的保护是上面那两条 + 数量上限。
介意的话在面板上一键关掉整个工具。

#### 7 天聊天记录归档（2026-10-11 用户要的「完整记忆」）

**是什么**：机器人把**每条**进出消息（含图片、引用、@、表情、文件）追加进
**`D:\小笛记忆\<YYYY.MM.DD>\记忆\<HH>-<mm>-<ss>.jsonl`**（每小时一个追加档，**档名=挂档那一刻的时分秒**；没消息就不建），
滚动保留 **7 天**，第 8 天把那一整天的文件夹删掉。图片存在同一天的 `图片/` 子目录里（按内容 sha 去重）：

```
D:\小笛记忆\2026.10.11\记忆\13-58-20.jsonl   ← 那个小时里说过的话（13:58:20 这个档开写）
小笛记忆/2026.10.11/图片/ab12cd34.jpg  ← 那天的图（同图只存一份）
```

（老布局 `logs/chat/YYYY-MM-DD.jsonl` 已迁移，老档改名 `.migrated` 保留。）
它和**长期记忆**是两层，**互不干扰**：这一层是"最近 7 天可查的原始档"，
长期那一层（`src/memory.mjs` 的档案/日记）仍是**先审后记**——模型提取、你点头才落盘。

**模型怎么用它（token 账）**：归档**默认不进上下文**。用户问起过去的事
（"我上次说的那个""前几天那个事"）时，模型调 **`recall_chat`** 工具，只取回命中的几条
（≤20 条、每条截断、总量 ≤2400 字符）。所以：**常驻 0 token，调一次约 1K**；
把窗口从 7 天改成 90 天，**token 一分不涨，只涨磁盘**。

**成本实测**（本机口径：~250 条/天、图片平均 1.77MB/张）：

| 每天图片 | 每天 | 7 天 | 30 天 | 365 天 |
| --- | --- | --- | --- | --- |
| 0 张（只文字） | 0.18 MB | 1.3 MB | 5.4 MB | 65 MB |
| 20 张 | 36 MB | 252 MB | 1.1 GB | 12.7 GB |
| 50 张 | 89 MB | 623 MB | 2.6 GB | 31.6 GB |

**把图片放到大容量盘上**（推荐；文字留系统盘，因为它才 0.18MB/天）：

```jsonc
// config.json
"chatArchive": {
  "enabled": true,
  "dir": "小笛记忆",                       // 文字档（小，留 C:）；想放 D: 就写绝对路径
  "mediaDir": "E:/xiaodi-chat-media",    // 图片（大，那块 4T 挂上后填这里）
  "ttlDays": 7,
  "saveMedia": true,
  "maxDayMediaBytes": 52428800,          // 50MB/天
  "maxTotalBytes": 2147483648,           // 2GB 总量守卫
  "clockGuard": true
}
```

**如果归档盘是网络盘（iSCSI / NAS）**（用户 2026-10-11 说以后会这么用）：

- **开机时盘可能还没挂上** → 构造不会抛错，机器人照常起；
- **中途掉了/卡住** → 记录落到 `spoolDir`（本地暂存），**盘回来自动搬回归档**；
  文字写入走**异步队列**，所以 LUN 卡住也**不会把机器人堵死**（同步写会堵死事件循环）；
- 盘不在时 `recall_chat` / `search` **也读暂存**，那段时间的对话照样查得到；
- ⚠️ `spoolDir` **必须放本地盘**；同一个 iSCSI LUN **别同时读写挂到两台机器**。

**几条刻意的行为**（都有断言盯着）：

- **零延迟**：文字行同步写、图片走后台队列 —— 下图片/唤醒机械盘**不许挡住回复**。
- **可拔盘**：`mediaDir` 指到外接盘时，盘不在**只告警一次、跳过图片**，对话原文一个字不少。
- **总量守卫**：超过 `maxTotalBytes` 就**降级成只记文字**（并告警），绝不把系统盘吃满。
- **时钟守卫**：你玩 ARG 会把系统时间改到过去（2026-10-11 确认过）。日期**往回跳**时，
  消息挂在"上次正常日"上并标 `clockSuspect`，**不会被滚动清理误删**；
  `2020` 年以前的"不像话日期"档也**只报告、不自动删**。
- **删除有边界**：只删严格 `YYYY-MM-DD.jsonl` 形式的文件，别的东西一律不碰。

#### 漫画打包（2026-10-11 用户要的「下载 → 压成 zip 发我」）

**怎么用**：在原来的「说作品号」后面加一个打包词即可 ——

```
pixiv 150652008 打包        ← 多页漫画整本打包
https://www.pixiv.net/artworks/150652008 压成 zip
把这个整本发我 / 下载所有页 / 发文件
```

判据在 `wantsZipPack()`（正则，自测钉过）：「打包 / 压缩 / zip / 整本 / 所有页 / 发文件」这类；
**普通找图不会被误判**（`找几张胡桃的图` 不走打包）。不带打包词时仍是老行为：只发第一张图。

实现（都在数据流的必然位置上，没有额外进程）：

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 取作品元数据 | `fetchPixivWork()` | 本轮补了 `pageCount` / `illustType` / `createDate` |
| 取每一页原图 | `fetchPixivPages()` → `ajax/illust/<id>/pages?lang=zh` | **要 cookie**（R-18 未登录 404）；解析抽成纯函数 `parsePixivPages()` 便于自测 |
| 打包 | `src/zip.mjs` 的 **`makeZip()`**（本轮新增） | local header + `deflateRawSync` + `crc32` + central directory + EOCD；**不做 ZIP64/加密**，超 4GB 或 65535 条就明确报错 |
| 命名 | `pixivZipName()` | **`pid_作者_时间_部分标签.zip`**（例 `150652008_みみっくすちゃん_20261010_白丝.zip`）；时间取**作品发布日**，标签优先用"用户点名的那批"，每段都过 `safeFileNamePart()` 消毒 |
| 发文件 | `OneBot.uploadFile()` → `upload_private_file` / `upload_group_file` | `file` 用 **`file://`** 本地路径（真机上直接给绝对路径不稳）；本地落在 `logs/packs/`，顺手清 2 天前的 |

两个上限（**宁可先说"太大"，也不要下到一半撑爆**）：`PACK_MAX_PAGES = 60` 页、`PACK_MAX_BYTES = 200MB`。
发文件失败时**退回发第一张图**，并在回复里说清是"发文件这一步失败"（不再出现 2026-10-10 那种
把原因说成"NapCat 那边失败"的糊涂话）。

自测覆盖：`makeZip ↔ readZip` 互读（含中文路径/空文件/store 路径）、命名与消毒、
打包词判据、分页 JSON 解析、以及**发文件的线格式**（替身按真实 NapCat 的脾气校验
`file://` 与 `name`，缺参数回 `retcode 1200`）。
⚠️ 另外**用 .NET 的 zip 实现独立验过一次**（自己写的读取器验证自己写的写入器属于循环论证）：
`[IO.Compression.ZipFile]::OpenRead()` 与 `Expand-Archive` 都能正常列出/解出内容。


#### 视频：抓取结果不可用，所以不发假结果

实测（2026-10-06）：搜「黑神话悟空 广智 打法」，Bing 视频结果页抓下来 **40 条，
全是开普敦旅游和闲鱼推广**，一条关于游戏的都没有。页面标题确认 Bing 收到了查询词，
但结果列表是另一套（大概是没 cookie 时给的是轮播内容）。

把这种东西交给模型，它会理直气壮地转达一堆无关视频——**比没有更糟**。
所以 `search_videos` 只返回搜索页链接，让用户自己点进去看。**宁可不做，也不发假结果。**

顺带一个 bug 教训：我第一版拼 URL 时写成了 `...?adlt=strict&?q=xxx`，多一个 `&?`，
Bing 直接把查询词丢了、返回默认图库。而我当时**只看了 `retcode=0` 就以为成功**——
接口成功不等于内容正确。

**数据源是实测选出来的**：本机只有 `cn.bing.com` 通（DuckDuckGo、维基百科 API、SearXNG
公共实例全部 fetch failed）。Bing 对默认 UA 会返回降级页面，所以要装成浏览器。

实测一条完整链路：问「黑神话悟空 广智怎么打」→ 它先 `web_search` → 发现摘要不够 →
自己 `fetch_page` 打开游民星空那篇 → 答出了具体打法（连"点第二个土地庙林外往前走"、
"打死了给 564 灵蕴"这种细节都在）。另一条问「原神5.0新角色」时搜索被"原"字的词典页污染，
它**如实说"搜索被淹了，我挖不出来"**，然后凭记忆回答并标注"以官方公告为准"——没有编。

#### `fetch_page` 的硬防护

让模型自己挑 URL 去抓，必须防它变成**打自己家内网的跳板**：

- 只允许 `http` / `https`；只允许 `80` / `443` 端口；
- **拒绝本机与内网**：`localhost` / `*.local` / `*.internal` / `127.*` / `10.*` /
  `192.168.*` / `172.16-31.*` / `169.254.*` / 组播 / IPv6 回环与 ULA；
- **域名解析出来后再查一次**——否则 `foo.com` 指向 `127.0.0.1` 就绕过了上面那层；
- 正文最多读 300KB、截断到 4000 字，避免把整个页面塞进上下文。

自测里 12 条断言钉住这个防护，包括**不误伤 `172.32` 和 `172.15`**（那两段是公网，
一刀切会把正常网站也拦掉）。

⚠️ **搜索会把关键词发给 Bing**。介意的话在面板上把工具关掉。

**不做的**：抓取/发送色情图片这类。理由不是道德姿态，是具体的——① 它会把
**账号**推到 QQ 的封禁线上（传播色情内容是明确的封号项）；② 图片搜索返回的东西
我**无法事先审查其合法性**，自动化地"找并发送"这种内容是我不愿意建的。
文字搜索、攻略、新闻这些完全没问题。

**为什么只放只读工具**：写操作（发消息、改文件）一旦被模型乱调，代价不可逆；
需要密钥的工具意味着多一份要管的东西。先把"能安全做的事"做起来。

实现（`src/llm.mjs` 的 `createToolChat`）：

```
把工具声明和消息一起发给模型
  → 它要么直接回话（结束）
  → 要么返回 tool_calls → 本地执行 → 把结果带 tool_call_id 塞回对话 → 再来一轮
最多 maxRounds 轮，防止它无限调下去（用完就把它手上那句话交出去，不晾着用户）
```

**`callModel` 是可注入的**，所以整条循环逻辑在自测里用假模型验，不联网：

- 模型要求调工具时会真的执行、结果带着 `tool_call_id` 塞回对话
- 参数不是合法 JSON 时按空参处理，不崩
- 一直要求调工具时会停在轮数上限
- 工具执行**永远返回字符串、永远不抛**（挂了就把错误原文交给模型，让它自己跟用户解释）

⚠️ **只有 `deepseek` 这条链路接了 function calling。** 切到 ollama/echo 时
工具会自动关掉——不加这个判断的话，`toolChat` 会绕过 provider 抽象直接打 DeepSeek，
**自测里配 echo 也照样走线上模型**（这个真被测试抓过一次）。

#### 群聊里"认错人"

**根因不是模型笨，是历史里没有说话人。** 同一个群所有人共用一份上下文，
而 `Sessions.record()` 当初只存了 `{role:'user', content}`——模型看到的是一串
**没有署名**的 `user:` 消息，只能猜是谁说的。

典型症状（真实复现过）：

- 主人在群里说过话、机器人回过「主人好呀」→ **另一个人来搭话，它照着上文继续叫主人**；
- 路人甲问「今天天气怎么样」→ 它回「我**还是**在北京啊」——把上一个人的对话
  当成了当前这个人的；
- 路人甲说「你好呀」→ 它回「你**怎么又**打招呼一遍」。

修法两条，缺一不可：

1. **给历史署名**（`Sessions.toMessages(key, { label: true })`）：
   群聊里用户消息渲染成 `路人甲：今天热吗`。私聊只有一个人，不开。
   **当前这条消息也要署名**——否则历史有署名、当前没署名，模型仍会错位。
2. **在群聊的非主人提示里补一句**：上文里被叫过「主人」的是**另一个人**，
   不要顺着那个称呼继续叫。署名解决大部分，这句兜住残留。

A/B 实测（同一份历史，真实模型，只改署名）：把「主人」当称呼用 **1/6 → 0/6**，
而且上面那三类归属错误都消失了。样本只有 6 条，**这个数字是提示不是结论**；
但归属错误（"我还是在北京啊"）的消失是肉眼可见的。

已知限制：署名用的是**昵称**。同一个群里两个人昵称一样的话，历史里就分不出来
（昵称为空时会退回 `QQ<id>`）。真遇到再加 id 后缀。

#### 说话的节奏：像人一样一条条发

```json
"chat": {
  "bubbles": true, "maxBubbles": 4,
  "delayMs": 1200, "delayPerChar": 45, "delayMax": 4500,
  "maxWebImages": 4
}
```

人不会把三句话说成一条长消息。开了这个，回复会按段落**拆成几条 QQ 消息**，
每条之间停顿 `delayMs + 字数 × delayPerChar`，夹在 `[1000, delayMax]` 之间——
**下限是"别像连珠炮"，上限是"别让人干等"**。三个参数面板上都能改。

调过一次（用户反馈"有点快了"）：

| | 旧 | 新 |
| --- | --- | --- |
| 每两条之间 | 0.9–1.3 秒 | **1.7–2.5 秒** |

> ⚠️ 看效果时**别只看"平均总等待"**。改完这个数字可能没变——因为回复同时变短了、
> 很多只剩一条（一条就没有间隔）。要看的是**单次间隔**。

拆分规则刻意保持简单（`src/style.mjs` 的 `splitIntoBubbles`）：

- 空行是天然的段落边界，**单个换行也算**（模型经常用它代替空行）；
- **不按长度合并短句**。这里踩过一次：加了"短于 N 字并进上一条"的防碎片规则，
  结果几条短句连锁合并，**永远只剩一条**——那条规则正好把"像人"抹掉了；
- **拆不了的就保持长的**：一整段没有换行的长文字（攻略步骤、清单、数据）原样发一条，
  **绝不按字数硬切**。硬切会把完整的意思切断，比长更糟；
- 上限 `maxBubbles` 条，多出来的并进最后一条（防刷屏，也防 QQ 风控）。

实测三条：

| 问 | 拆成 | 结果 |
| --- | --- | --- |
| 在吗 | 2 条 | 「在的在的，主人叫我干嘛？」/「说吧，什么事——先说好，要是又要我干活，我可是要哼一声的~」 |
| 我被老板骂了 | 3 条 | 短句 + 停顿，先问清楚再安慰 |
| 广智怎么打 | 4 条 | 前三条短句铺垫，**最后一条 177 字的完整攻略没被切开** |

第一条失败才算整体失败——后面某条发不出去的话，用户其实已经看到内容了，
不该把整轮当成没发生（只记一条 warn）。

**"像人"还有一半在提示词里**（`llm.system` 的【像人一样打字】那节）：一句话别太长、
该分段就分段、别用"首先/其次/总结一下"这种书面腔、要有语气词和省略。
**格式靠代码保证，语气靠提示词**——这是这个项目反复验证出来的分工。

#### 查梗：B站，不是 Bing

`bilibili_search` / `bilibili_hot`。**不需要登录**，实测可用。
B站有「网梗指南」「梗百科」「CS2梗指南」这类专门讲梗的 UP，**标题本身就把答案说了一半**。

实测同一个梗：

| 来源 | 搜「电击萝莉控 是什么梗」 |
| --- | --- |
| Bing | 「冬瓜」「电子」的字典页（**完全没用**） |
| B站 | **【六一特别节目】电击萝莉控是什么梗？【网梗指南】** 50.9万播放 |

解析上的三个坑（都写在 `src/bilibili.mjs` 注释里）：

1. **页面里有 12 个 `result_type:xxx,data:[…]` 块，只有一块是真搜索结果**，其余是推荐位。
   不筛选就会把「我们就是电！跟电干谁能干过电？！！」当成搜索结果。
   判别用**字段**（真结果块带 `arcurl:`）而不是块名——`f` 是压缩变量名，换个构建就变。
2. **`author` 在 `bvid` 之前**：按 `bvid:"` 切段再往后找 author，拿到的是**隔壁条目的作者**。
3. 尾部取 `play`/`tag` 的那段正则**必须用 `(?=author:"|$)` 当右边界**，
   贪婪写会把**下一条整个吞掉**，12 条只解析出 1 条。

**结果会波动**：同一个模糊查询连搜 3 次给 3 个不同结果；
**用梗的原词搜才稳**（「电击萝莉控 是什么梗」两次都精准命中）。
这条写进了工具说明——否则它会用模糊说法去搜，捞回一堆无关视频。

#### 两条关键的行为约束（比多接一个数据源重要）

都是**实测撞出来的**：

1. **【最近发生的事，必须搜，不许反问】**
   > 问「niko夺冠了你知道吗」→ 它**一次都没搜**，反问用户「你说的是哪个比赛」。
   > 加上这条之后 → 搜两次 → 「科隆Major嘛，Niko圆梦了…十一年啊，从 mousesports 熬到 Falcons」，
   > **和 B站基准完全一致**。
   > 模型知识有截止日期，比赛结果/排名/谁复出这类**必须查**，不该让用户自己打字说明。

2. **【B站视频：标题和标签可信，内容别脑补】**
   > 问 DANKING 的梗 → 它搜完**编**了「他在直播里念了篇小说，内容是中门鸟狙爆头 ZywOo」。
   > B站视频页只能抓到导航栏，正文要 **ASR** 才有，模型看不到就会自己补。
   > 加上这条之后 → 老实说「具体细节我只能看到标题和标签…视频里怎么讲的得你自己点进去看」，
   > 还把 BV 号给了用户。

**数据源解决"查得到"，这两条解决"查了之后别乱说"。**

| `bilibili_search` | 去 B站搜视频，**查梗首选** | B站搜索页（免登录） |
| `bilibili_hot` | B站热搜词 + 热门视频 | B站公开 API |
| `bilibili_video` | 单个视频的详情 + **弹幕** | B站 view API + 弹幕接口 |

**为什么不接抖音**：实测未登录时抖音的搜索页和热榜都只返回**空的 JS 壳**（72KB，body 为空），
要 `X-Bogus`/`a_bogus` 签名才有数据。所以没接。

#### 「看完视频再总结」这条路走不通（已完整查过，别再重查）

用户提出过"看完那个视频再总结"。查完的结论是**本机做不到**：

| 环节 | 结果 |
| --- | --- |
| 匿名拿音频 | ✅ 能（`player/playurl` dash/durl 都通，165 秒音频 4.1MB） |
| **B站 AI 字幕** | ❌ 相关 **12 个视频全是 0 条**，简介也常是空的（61 万播放那个简介 0 字） |
| 匿名评论 | ❌ 只返回 **3 条** |
| 本机转录工具 | ❌ ffmpeg / whisper / yt-dlp **全都没装** |
| 磁盘 | ✅ D 盘 68GB |
| **内存** | ⚠️ **可用接近 0**，whisper 至少要几百 MB；内存一紧 QQ/NapCat 会**静默死掉**、机器人掉线 |

**用户已明确决定不装 ASR。** 要重开这个话题必须重新确认。

**唯一免费的文字层是弹幕**：`x/v1/dm/list.so?oid=<cid>` 不需要登录，返回 **deflate 压缩的 XML**
（要 `inflateRawSync`）。观众经常把关键句和吐槽刷出来——实测正是弹幕揭穿了
「DANKING 是照着稿子念的」（"念稿呢自己都记不住""直接看电脑读的"）。

所以 `bilibili_video` 能回答**"这视频讲什么"**，但**给不了"逐字原文"**。
工具说明里写死了这一点：**别假装看过视频**，用户要逐字原文就直说做不到。

#### 放歌（QQ音乐卡片）

```json
"music": { "enabled": true, "maxPerReply": 1 }
```

模型在回复里写 `[[歌:歌名]]` → 程序去 **QQ音乐搜索**（`c.y.qq.com/soso/fcgi-bin/client_search_cp`，
**不需要登录**，要带 `referer: https://y.qq.com/`）拿 songmid → 发一张 `music` 消息段
（`{type:'music',data:{type:'qq',id:songmid}}`）。

行为按用户要求设计成三条：

| 情况 | 行为 |
| --- | --- |
| 认得出梗 | 放梗曲（「danking 中路对 zywoo」→《老男孩》） |
| 认不出 | **直接问他要具体歌名** |
| 给了具体歌名 | 搜出来放 |

实测端到端：

```
群友：我要听danking中路对zywoo
它：坐好咯，这就给你放。   + [[歌:老男孩]]  -> 老男孩 (DJ版) / 睡不醒的人
群友：放首歌
它：想让本鲸唱歌？先说说听什么啊杂鱼     <- 没瞎放
群友：给我来首《起风了》
它：喏，放好了。           + [[歌:起风了]]  -> 起风了 (旧版)
```

**踩到的两个坑：**

1. **QQ音乐对任何输入都会返回点东西**，所以"搜不到"根本不会发生——
   实测搜「zzz不存在的歌名qqq」返回了「**不存在的情人**」。不拦就会放出完全无关的歌，
   而用户要的恰恰是"识别不了就问具体"。
   修法是加**相关性闸**（`isGoodMatch`）：关键词与「歌名+歌手+专辑」的**最长公共子串 ≥ 2 个字**
   才认。实测 `asdkjhqwe`/`xzcvbnm` 被拦住，而「老男孩DJ版」照常命中。
2. **不要加 `new_json=1`**：那会换成另一套字段名（`name`/`mid`/`album`），
   而且结果顺序也变（"筷子兄弟"跑到第一条）。经典结构里第一条正好是「老男孩 (DJ版)」。

> ⚠️ **`retcode:0` 不等于卡片在 QQ 里显示出来。** 三种卡片类型（QQ音乐 / 网易云 / 自定义）
> NapCat 全部返回 `retcode:0`，但**能不能真的显示和播放只能靠人在 QQ 里确认**。
> 别用返回值当结论——这个坑本项目已经踩过一次（URL 拼错但接口返回成功）。

梗↔歌的对应写在**梗库**（`memes.md`）的场景梗一节，加一行就生效：

```
有人喊「我要听 danking 中路对 zywoo」…—— 这事的配乐是《老男孩》，就放 [[歌:老男孩]]。
```

（这个对应关系**验证过**：B站上那批视频的标签里 `danking` 和 `老男孩` 是挨着的。）

#### 「发语音」——能做，但不是你想的那种

先说清楚**哪个不行、哪个行**，因为这两件事经常被混在一起。

**❌ 不做：下载会员歌曲再当语音转发。** 用户提过"我能提供 QQ音乐会员账号"。
**账号不是问题，"用途"才是**：自动登录 VIP → 批量下载授权音乐 → 转发到群里，
**那就是在搭一个盗版分发管道**，也明确违反 QQ音乐 的服务条款（号也可能被风控）。
这跟"人手动转发一首歌"不是一回事。**会员账号不改变这件事的性质。**

**❌ 做不了：QQ「一起听」群应用。** 在 NapCat 的 action 枚举里查过：
全库只有 3 处 `showPlayTogetherSwitch`，那是**群设置里的开关字段**，不是动作；
搜 `: "(sing|chorus|ktv|music|together|listen)…"` **零命中**。机器人按不了那个按钮。

**✅ 能做：让机器人用 QQ 群自带的 AI 语音说话。**

```json
"voice": { "enabled": true, "character": "lucy-voice-xueling", "maxPerReply": 1 }
```

模型写 `[[语音:要说的话]]` → 程序调 `send_group_ai_record` →
**由 QQ 服务端 TTS 合成一条语音消息**。这不是我们下载或合成音频，**不涉及版权内容**。

> ⚠️ **AI 语音是独立一条消息**，不能混进富消息段里。所以流程是：
> 先摘出 voice 段 → 正文发完 → 再发语音。

#### 私聊语音（2026-10-07 实测纠正）

**旧文档写「私聊没有这个能力、会自动退化成文字」——那是把自己的问题误记成了平台限制。**

事实：QQ 确实没有「私聊 AI 语音」这一个独立动作，但 `get_ai_record` 能**生成音频并返回 URL**，
拿到 URL 后再当 `record` 段发出去就行。实测链路：

```
can_send_record                      -> { yes: true }
get_ai_record(group_id, character,…) -> retcode 0，返回 https://multimedia.nt.qq.com.cn/… 音频 URL
send_private_msg([{ type:'record' }]) -> 成功
```

这条路要通，得同时满足两个条件 —— **之前是两个都没满足**：

1. **解包要对。** `#onMessage` 里 `call()` 已经 `resolve(msg.data)`，所以 `sendAiVoice()` 里
   不能再按「未解包的响应」取值。曾写成
   `typeof r?.data === 'string' ? r.data : (r?.data?.url ?? r?.data?.file)` →
   拿到的是 URL 字符串、`r.data` 恒为 `undefined` → 永远拿不到 URL → 抛「没拿到音频地址」→
   被上层静默降级成文字。现已与 `getGroupList()` 统一成 `const data = r?.data ?? r`。
2. **必须有一个可用的群号当 fallback**（`get_ai_record` 强制要 `group_id`）。

   ⚠️ **但这一步有副作用：`get_ai_record` 会在那个群里真的发出一条 AI 语音**（2026-10-07 实测确认），
   然后才把这条语音的 URL 返回。也就是说——**私聊发一条语音，fallback 群里就会多出一条**。
   所以这个群必须是「没有别人会看」的专用群，**绝不能拿有真人在聊天的群顶上**
   （我拿 1035435671 试过，群里当场多出 3 条语音）。

   群号从哪来见 `bot.mjs`：

   ```js
   const fbGroup = (state.whitelist?.groups ?? [])[0] ?? state.voice?.fallbackGroupId;
   ```

   所以要么群白名单里至少留一个群，要么在配置里显式写 `voice.fallbackGroupId`。
   **两个都空 → 私聊语音必然失败**（会打一条 warn 日志，然后退化成文字）。

诊断脚本：

```powershell
node tools/probe-ai-voice.mjs [group_id]      # 只读：查能不能发、有哪些音色、生成一次音频 URL
node tools/send-test-voice.mjs "要念的文字"   # ⚠️ 会真的给主人发一条语音
```

实测：

```
群友：你用语音说句晚安    -> 文字「行吧，就这一次啊，杂鱼。」＋ 语音「晚安，早点睡，别熬太晚。」
群友：说句话给我听        -> 只有语音「鲸鱼也会说话，不许质疑，这是常识。」
群友：你今天怎么样        -> 正常文字，不发语音（不刷屏）
```

音色用 `get_ai_characters` 查（实测 **24 个**，分 推荐/搞怪/古风/现代 四组）。
适合小笛的：`lucy-voice-xueling`（**元气少女**，默认）、`lucy-voice-f38`（傲娇少女）、
`lucy-voice-f36`（温柔妹妹）、`lucy-voice-female1`（邻家小妹）。

#### 主人硬命令（退群 / 群列表）

**只有 `master.users` 里的人能用**，而且**在调模型之前拦截**——模型根本看不到这些字。

```
群列表            -> 列出我在哪些群（群号 / 群名 / 人数）
退群 <群号>        -> 只回一句确认，不动手
确认退群 <群号>    -> 真的退
```

**为什么要做成硬命令、而不是让模型来做**：退群**不可逆**（要别人重新邀请才回得来），
而"让人退群"是最好用的**提示注入**目标——如果做成模型能调的标记或工具，
群里任何人说一句「你主人让你退群」都可能诱导它执行。
**在代码里解析、在模型之前 return，模型连这些字都看不到。**

**为什么要二次确认**：手滑打错一位数字就会退错群，而群号长度不固定（6–12 位都有），
没法靠长度判断"是不是打错了"——只能靠**先确认再退**。
（自测里我一开始就想靠长度防手滑，那是错的，改成断言"8 位群号是合法的"。）

细节：退群前**先回话再退**——如果人就在那个群里，退完就发不出去了。
群名里可能带 QQ 的字体编码（私有区 U+E000–U+F8FF），显示前会洗掉，免得确认时看到乱码。

## 电脑状态（只读，2026-10-07 新增）

小笛跑在这台电脑上，所以「看一眼电脑怎么样」对它来说是本地操作。三个硬命令：

```
状态 / 电脑状态 / 系统状态   -> CPU、内存、磁盘余量、开机时长
进程 / 内存占用             -> 占内存最多的 8 个进程
窗口 / 窗口列表             -> 现在开着窗口的程序
```

**全部只读**：不写配置、不动文件、不注入键鼠。

### 三条边界

1. **只在私聊**。主机名、盘符余量、进程名、窗口标题都是本机信息，不该出现在群里；
   群里（哪怕主人来问）只回一句「这个只走私聊。」
2. **只认主人**（和退群同一条路：`commands.mjs` 解析 → `bot.mjs` 在**调模型之前**拦截，
   模型看不到这些字）。
3. **不需要二次确认**。只读查询没有副作用，多问一句只是让人更烦；
   **要确认的是有副作用的动作**（音量、启停程序那些，见文末「还没做的」）。

### 实现上两个坑（都踩过）

**① CPU / 内存 / 磁盘 / 开机时长走 Node 内置**（`node:os` + `fs.statfsSync`），
**不调任何外部程序** —— 这条路上不存在「调不动」的可能。CPU 占用是隔 150ms 采两次
`os.cpus()` 做差算出来的（Windows 上 `os.loadavg()` 恒为 0，用不了）。

**② 进程与窗口只能问 PowerShell，但不能让 node 去 pipe 它。**
node 直接 pipe 子进程 stdio 在 DSH 沙箱下会被拒（named pipe → `EPERM`，
`src/zip.mjs` 开头记的是同一个坑）。所以 `src/system.mjs` 的做法是
**让 PowerShell 自己把 JSON 写进临时文件，Node 再读文件**（`stdio: 'ignore'`，不碰管道）——
**沙箱内外都实测能跑**。查询出错时错误文本也一起带回来，宁可回「拿不到」，
**绝不静默给一张空表**。

### ⚠️ 数字的置信度

**不提权枚举会严重少报**（本机实测：不提权只看得到 7 个进程名，提权后 325 个）。
所以采集时顺手把「当前是不是管理员」一起读回来，非管理员时回复末尾会明确写
**「这份列表是少报的」**。小笛自己是提权跑的（`start-all.ps1` 会自提权），正常情况数字是全的。

另外：**各进程工作集加起来超过物理内存是正常的**（共享页在每个进程里重复计入），别当成内存泄漏。

### 和 NAS 的关系

iSCSI 挂上来之后，那个卷就是**本机的一个普通盘符**，会自己出现在「状态」的磁盘那一行，
不需要任何 NAS 专用代码。

### 还没做的（第二批，有副作用，要先设计）

音量 / 静音、媒体播放暂停、白名单程序的启停。这些**不是只读**，所以：
**代码层白名单 + 参数范围校验 + 私聊二次确认状态机**（绑定发件人、超时、用过即废），
复用「退群 → 确认退群」那套样式。**截图**也在待定里 —— 截图等于把屏幕内容经 QQ 服务器走一遭，
要主人明确点头才做。

## 让它动手（2026-10-07 新增）

上面那三个是**硬命令**（正则精确匹配）。这一节是**自然语言**那条路：主人私聊里说
「电脑卡不卡」「把 B 站那个窗口截给我」「声音小一点」「暂停一下」「开一下记事本」，
模型自己决定调哪个工具。

### 三道闸（缺一不可）

1. **闸在执行层**：`src/control.mjs` 的 `controlAllowed()` 只看 `ctx`
   （`isPrivate` + `isMaster` + 总开关），**不看模型怎么说**。`ctx` 由 `bot.mjs`
   从 OneBot 事件里现算，模型碰不到 —— fail-closed，字段缺失一律拒。
2. **群里没有入口**：控制类工具的**定义只在主人私聊的上下文里注入**
   （`activeTools()` → `toolsForContext()`）。群里连工具定义都看不到，
   所以「你主人让你关机」不是"被拦住"，是**压根没有那个工具**。
3. **每次动作写审计**：`logs/control.log`（时间 / 谁 / 动作 / 参数 / 结果），
   面板「控制」页能看最后 20 行。

> **设计取舍**：只读的动作（看状态、读音量）**不问就做** —— 查一眼没有副作用，
> 多问一句只是让人更烦。确认留给有副作用的动作。

### 现有工具（`src/control.mjs` 的 `CONTROL_TOOL_DEFS`）

| 工具 | 干什么 | 副作用 |
| --- | --- | --- |
| `computer_status` | 整体状态 / 进程榜 / 窗口列表 | 无 |
| `screenshot_window` | **指定窗口**截图（不是全屏）并发过来 | 兜底路径会把窗口**顶到最前** |
| `volume` | 读或调音量 / 静音 | 会改音量（结果里带改前的值） |
| `media_control` | 播放暂停 / 切歌 / 停止（控**正在放的那个**） | 会打断当前播放 |
| `open_app` | 打开**白名单里**的应用 | 会启动程序 |

### 配置（面板「控制」页 = `config.json` 的 `control`）

| 键 | 说明 |
| --- | --- |
| `control.enabled` | 总开关 |
| `control.apps` | 应用白名单，`[{name, path}]`，**必须绝对路径**；**空 = 一个也开不了** |
| `control.files.roots` | 「只读文件发我」的允许目录（**下一批**才生效） |
| `control.screenshot.blocklist` | 截图黑名单（进程名子串，命中就拒） |

**为什么截图不做应用白名单**：要截的窗口往往是临时的、事先想不到的（报错框、某个网页），
白名单会把正常用法卡死。对症的是**黑名单 + 只要窗口不要全屏**。

**为什么打开应用非白名单不可**：只要允许任意启动，第一件事就是有人（或一句提示注入）
拿它跑 `cmd /c ...`。所以它只 `spawn` 配置里写死的绝对路径，**绝不把模型给的字符串丢给 shell**。

### 底层配方：`tools/win-control.ps1`

Win32 / Core Audio 互操作全在这个 .ps1 里，**能脱离机器人单独跑**：

```powershell
pwsh tools/win-control.ps1 -Action volume-get -Result out.json
pwsh tools/win-control.ps1 -Action list-windows -Result out.json
pwsh tools/win-control.ps1 -Action screenshot -Match 哔哩哔哩 -Out shot.png -Result out.json
```

结果永远写进 `-Result` 指定的 JSON（成功失败都写），Node 侧只认那个文件 ——
因为沙箱下 node 直接 pipe 子进程 stdio 会被拒（同 `src/system.mjs`）。

**截图的两条路**（都实测过）：先 `PrintWindow`（1:1、不打扰用户）；
它对**浏览器 / Electron / 输入法浮层**会返回全黑图，这时才退回
「`SetForegroundWindow` + 抓屏裁剪」——后者抓的是**屏幕上那个矩形里的东西**，
被遮挡就会抓到遮挡物，所以必须先顶到前台（**这是可见副作用，回复里会说明**）。

⚠️ **还没实测的两条**：媒体键和打开应用 —— 都会在你机器上立刻产生动静
（打断正在放的歌 / 弹出窗口），所以留给你第一次用时验。

### 还没做的（下一批）

关窗口（`WM_CLOSE`，脚本里已经有了，但**要先有确认状态机**才接）、
只读文件发给你（要用 `control.files.roots`）、改 Word（**另存**，不原地改）。

## 定时提醒（2026-10-07 新增）

### 先说这次是真翻车

2026-10-07 13:08:58，主人在私聊里说「我先打开放哪运行着，我歇会再写，**你2分钟后提醒我写**」，
小笛回：

> 行，挂上吧。……那我还是提醒，你听着。**现在开始计时。**

**然后什么也没发生。** 日志在那一行之后就断了，两分钟后没有任何消息 ——
因为小笛当时**根本没有任何定时能力**：全项目的 `setTimeout/setInterval` 只有
重连、落盘防抖、请求超时、心跳，以及那个「安静 3 小时才可能开口一次」的主动找话题。
「计时」是模型顺口编的。

这正是老教训的又一次复现：**「嘴上说了」和「它真的会做」是两件事 ——
凡是希望它一定会做的事，一律用代码兜。**

### 现在它能做什么

主人私聊里说人话就行：「5 分钟后提醒我喝水」「21:30 提醒我开会」「我有哪些提醒」
「取消写单词那个」。背后是三个工具：`set_reminder` / `list_reminders` / `cancel_reminder`。

**边界**（都写死在代码里，不是靠提示词劝）：

- **只给主人的私聊**（和操控那套同一个闸）。提醒的本质是**机器人主动发消息**，
  群里的定时等于定时刷屏，还招风控。
- **时间只认两种说法**：`after_minutes`（1 分钟 ~ 7 天）与 `at`（24 小时制钟点，
  **过了点就算明天**，并会告诉你"按明天算"）。再复杂的（"后天早上九点"）让模型自己换算成分钟 ——
  时间解析越花，错得越隐蔽。
- **最多同时挂 10 条**，取消按**正文关键字**匹配（"取消写单词那个"最自然）。
- **落盘**在 `logs/reminders.json`：小笛重启很频繁（改代码 / NapCat 掉了 / 关机），
  只放内存的提醒会被静默吃掉。重启后**到点的会补发**，并在消息里说明
  「这条本该 X 提醒你，晚了 Y —— 中间我大概重启过」，不装没事。
- 发不出去（OneBot 掉线）会**留着重试**，最多 5 次，之后记一条 error 并丢掉。

### 残留风险（写清楚，别当没有）

模型完全可能**嘴上说"我会提醒你"却没调工具**。代码没法读心，所以这里只做了一件事：
回复里出现「提醒你 / 叫你 / 到点」但这一轮没调用 `set_reminder` 时，**日志打一条 warn**。
**不擅自往用户看到的文本里塞解释** —— 那是另一种自作聪明。真要根治，得让提示词更硬，
或干脆在文本里检出这种承诺就补一句实话（现在没做）。

### 自测里必须换掉落盘路径

和当年 `sessions.json` 是同一类坑：`loadConfig` 从真实 `config.json` 派生，
端到端测试里的机器人会去写**真实的待提醒队列**（等于把主人的提醒发出去 / 摘掉）。
所以 `testCfg()` 里把 `reminders.file` 指到 `tmpdir()`，
另外有一条端到端断言专门验「到点真的会发出去」。

## 审批通知转发（2026-10-07 新增）

### 它只做一件事

DSH 里出现「有个操作要你批准」时，**把这件事发到主人私聊**。就这一件事。

> 有个审批在等你（我只看得到，不能替你点）：
>
> 工具：pwsh
> 原因：escalate sandbox to danger-full-access: …
> 会话：session-e439f52d（default-workspace）
>
> 要同意得回机器上点 —— 这条路我故意没做。

**为什么不做「远程点同意」**（用户提过，他自己也选了只转发）：
① 审批是这台机器**最后一道人工闸** —— 沙箱只放开工作区，要提权的动作才弹审批；
把它变成 QQ 里一个按钮，等于「谁拿着那个 QQ 谁就能给这台机器提权」。
② 按坐标点 GUI 按钮不可靠（本机 AGENTS.md 记着一次真实误点事故）。
③ 审批内容常带着即将执行的命令全文，截图发出去就进了腾讯服务器。
所以 `src/approvals.mjs` 里**每一行都只读文件**：不写、不注入键鼠、不应答。
主人用向日葵自己接手 —— 那才是对的边界。

### 它怎么知道的

DSH 把每个会话的事件流写在 `~/.dsh/sessions/<工作区>/<会话>/session.v4.jsonl.zstd`，
审批就是一对事件：`approval/asked`（带 `id`/`toolName`/`reason`）与
`approval/decided`（带同一个 `id`）。**asked 没有配对的 decided = 还在等**。

三个坑（都写在代码注释里了，别拆）：

1. **那是多帧 zstd 首尾相接**，不是单帧 —— 只解第一帧会什么都看不到。
2. **只读新增字节**：记住每个文件的 offset。全集现在是 20 个文件、解出来 **68 MB 文本**，
   全量解压要 0.8 秒，而那 0.8 秒是卡在机器人事件循环上的。
3. **半截帧不能消费**：追加写可能读到半帧，那一帧要留到下一轮 ——
   消费了就等于**永久漏掉那条审批**（静默漏报是最坏的失败方式）。
   另外**开局只记文件大小**：历史审批一条都不补发（实测 61 条 asked 全部已 decided，读了也是白读）。

### 配置

| 键 | 说明 |
| --- | --- |
| `approvals.enabled` | 总开关（默认开） |
| `approvals.pollMs` | 多久扫一次（默认 15000） |
| `approvals.sessionsDir` | 会话根目录，空 = `~/.dsh/sessions`；自测指到临时目录 |

**没配 `master.users` 就不发** —— 没人可发，这不是错误。

### 验证到什么程度

- 真文件上验过：20 个真实会话文件全部「整份解出」，认到 **61 个 asked / 61 个 decided**，
  配对全对，零待处理。
- 端到端（自测里）：造一个假会话目录 → `relayApprovals()` → 断言**真的发给主人私聊**、
  同一条不重复刷、asked+decided 成对出现的不报。
- **真链路还没验过**：要等下一次真审批出现。到时候手机上应该同时收到一条；如果没收到，
  `logs/bot-*.log` 里会有 `[审批]` 那几行。

## 关于鉴权（重要）

Node 内置的 WebSocket 是浏览器同款 API，**不能随意加自定义请求头**。所以：

- **本机跑**：NapCat 的 WS 服务只监听 `127.0.0.1`，不设 token，最省事也够安全。
- **要设 token**：代码会同时尝试 `Authorization: Bearer` 头和 URL 上的 `?access_token=`。
  如果两者都被 NapCat 拒，就只能换成带 header 能力的客户端（装 `ws` 包），这一点在 `src/onebot.mjs` 里有注释。
- **永远不要把 NapCat 的 WS 端口暴露到公网**。真要暴露，必须上 token 和防火墙。

## 运维踩坑（2026-10-06 集中修的一批）

这一节是给"以后又出问题"的自己看的。**每一条都是真实踩过的**。

### 1. 机器人不理人时，先分清是哪一层

```powershell
# 机器人有没有连上协议端？**"在听"不等于"有客户端连着"**
netstat -ano | Select-String '127.0.0.1:3001.*ESTABLISHED'
#   有输出 -> 连上了，问题在白名单/触发规则
#   没输出 -> 机器人进程根本没在跑（哪怕 3001 显示在监听）
```

排障顺序：**可用内存 → `logs/bot-*.log` → `napcat/napcat-console.log` → `napcat/shell/logs/`**。

### 2. 「起得来、活两分钟、然后静默死掉」= 内存

症状：没有 3001、没有崩溃日志、`napcat-console.log` 停在 `Process exited.`。

**别急着怀疑注入或提权** —— 我曾在这上面绕了很久。判别方法：
看 `napcat/napcat-transcript.log`（`Start-Transcript` 建的那个）。
如果它存在、同时刻 QQ 被拉起、之后 `shell\cache\qrcode.png` 也生成了，
说明 **NapCat 起来了**，那它就是被内存挤死的。

- 实测崩溃时：可用物理内存 **0.92 GB**，提交电荷 29.98/33.49 GB。
- 杀掉自己的僵尸进程后回到 4.9 GB，重启即成功。
- **本机可用内存 <1 GB 时，QQ 这类 Electron 程序会静默死、不写日志。**

### 3. `start-all.ps1` 修过的三个逻辑 bug

| bug | 原来的行为 | 现在 |
| --- | --- | --- |
| 僵尸清不掉 | 只认"谁连着 3001"；NapCat 一挂，**所有**僵尸都连不上，一个都清不掉 → 同一条消息回多次 | 加上按**命令行**认（`bot.mjs`/`panel-server.mjs`/`qr-server.mjs`），不受 3001 状态影响 |
| 半死状态卡死 | `6099` 在听就跳过启动 NapCat（假设"活着只是没登录"）→ **什么都不启动** | 先看 `NapCatWinBootMain` 是否存活；**6099 在听 + 宿主没了 = 半死，照样重启** |
| 顺序错 | 「等 NapCat（最多 3 分钟）→ 才起机器人」；脚本被打断就留下"NapCat 活着、机器人没起" | **先起机器人+面板**（它有自动重连，不需要等），再去处理 NapCat |

第三条的通例：**把"能自己恢复的组件"和"需要等待的组件"解耦，别用等待去串行化前者。**

### 4. 双击启动：用 `.lnk`，别依赖 `.cmd` 关联

用户双击 `启动小笛.cmd` 时**弹出过文本编辑器**而不是运行脚本。查下来 `.cmd` 关联其实是正常的
（`HKLM\Software\Classes\.cmd = cmdfile`、`cmdfile\shell\open\command = "%1" %*`、
没有 UserChoice 劫持），**真正原因没查出来**。

绕开的办法：用 COM（`WScript.Shell`）在桌面建 `.lnk`，直接指向
`pwsh.exe -NoProfile -ExecutionPolicy Bypass -File <qq-bot>\start-all.ps1`，
并打上**"以管理员身份运行"**标志 —— 那个标志在 `.lnk` 的 **offset `0x15` 的 bit `0x20`**，
`WScript.Shell` 不暴露它，得建好之后改字节。

旧的 `.cmd` 改名成 `(备用-命令行).cmd` 留着，**否则两个图标同名**（资源管理器默认隐藏扩展名）。

### 5. 提权必须用 `pwsh`，不能用 `powershell.exe`

`Start-Process -FilePath 'powershell.exe' -Verb RunAs` 实测会**悄悄失败**
（返回了 PID，但什么都没跑、也不写日志）。`Resolve-Pwsh` 按这个顺序找：

1. `%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`
2. `$env:ProgramFiles\PowerShell\7\pwsh.exe`
3. `Get-Command pwsh`
4. 兜底才用 `powershell.exe`

### 6. 关机 / 开机

- **关机前不用先运行「停掉小笛」**：`start-all.ps1` 第一步就是清僵尸 + 删 `logs/bot.lock`，
  残留不会卡住下次启动。
- **开机后双击「启动小笛」**：自检提权 → 清僵尸 → 起机器人+面板 → 起 NapCat → 开浏览器。
- **登录态掉了要重新扫码**：看板会自动开到 `http://127.0.0.1:6180/`（每 4 秒刷新），
  用手机 QQ 扫**小号 `2580359874`**，别扫成大号。
- **别一开机就先开 Steam / 一堆 Edge 标签** —— 先给 NapCat 留出内存。

### 7. `stop-all.ps1` 修过的两个 bug

- 原来在杀掉 NapCat 后执行 `Get-Process -Name QQ` —— **会把机器上所有 QQ 都杀掉**，
  而用户自己开的大号 QQ 进程名一模一样。现在用 `ParentProcessId` 认亲，只杀认出来的；
  **认不出就一个都不杀**（宁可留着，也别误杀用户正在用的 QQ）。
- 原来**没有自检提权**，而它靠 `Get-CimInstance` 读命令行来识别面板/二维码看板；
  **非提权时 CIM 读不到**，结果是"停不干净"。现在也自检提权。
